# Правила разработки Conflict & War

Обязательные принципы закреплены в [конституции GitHub Spec Kit](../.specify/memory/constitution.md).
Процесс и команды — в [короткой памятке](sdd/README.md).

## Стек и границы

Текущий стек является базовым решением проекта: C++20/C11, Rust workspace,
CMake >= 3.25 с Ninja и Clang, vcpkg с baseline из vcpkg.json;
SDL3, OpenGL 3.3, OpenAL Soft, ImGui, Catch2 и Trident.
Состав зависимостей и закреплённые версии сохраняются.
Cargo.lock хранится в Git; CI использует `--locked`.

Смена технологии допустима только после воспроизводимого блокера, проверки
возможностей существующего стека и ADR с ценой миграции. Решение принимает
владелец проекта. Перенос на macOS сам по себе не является основанием менять стек.

## Антипаттерны

При обнаружении предложения или кода с антипаттерном разработчик или агент
явно сообщает **АНТИПАТТЕРН: название**, указывает место, вред и безопасный вариант.
До исправления новый антипаттерн не включается в изменение.

| Случай | Правильное действие |
| --- | --- |
| Игнорирование ошибки, пустой catch, возврат ложного успеха | Передать ошибку с контекстом или обработать документированный сценарий |
| Отключение теста или предупреждения ради зелёного CI | Найти причину; отдельно зафиксировать существующий дефект |
| Глобальное изменяемое состояние и скрытые зависимости | Явно передавать зависимость и определить владельца/время жизни |
| Дублирование логики, платформенные ветки по всему приложению | Использовать существующий модуль и локализовать различия в платформенном слое |
| Универсальная абстракция без реальной потребности | Реализовать минимальное решение текущего требования |
| Абсолютный путь к машине разработчика, секрет в исходнике | Использовать параметры/окружение, проверять наличие зависимостей |
| Полная перепись legacy вместе с небольшой задачей | Ограничить изменение требованиями; выделить рефакторинг отдельно |

Унаследованные глобальные подавления предупреждений в CMakeLists.txt остаются
техническим долгом, а не образцом для новых изменений. Их массовое удаление
требует отдельной спецификации и проверки всех платформ.

## Готовность изменения

Требования и приёмка согласованы с реализацией; задачи отмечены по факту;
проверки приложены с результатами. Для платформенного изменения нужны Windows
и macOS; недоступный прогон явно отмечается как непроверенный. Запуск игры с
данными, упаковка, подпись и notarization проверяются отдельно от компиляции.
