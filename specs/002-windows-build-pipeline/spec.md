# Feature Specification: Повторяемая Windows-сборка C&W

**Feature Branch**: используется текущая рабочая ветка; каталог 002-windows-build-pipeline.
**Created**: 2026-10-27
**Status**: Verified — Windows x64 RelWithDebInfo, полный и повторный конвейер успешны.
**Input**: Скомпилировать проект на Windows и подготовить конвейер зависимостей,
чтобы дальнейшая разработка не требовала ручного восстановления окружения.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Первая сборка из обычного терминала (Priority: P1)

Разработчик запускает одну документированную команду из корня проекта.
Она обнаруживает установленный набор разработки, подготавливает недостающие
локальные зависимости и собирает проект без ручного редактирования путей.

**Why this priority**: Реальная рабочая сборка — цель задачи.
**Independent Test**: На текущем Windows x64 host получить все C++ и Rust binaries
и успешное завершение базовых тестов.
**Acceptance Scenarios**:
1. **Given** установленный набор разработки Windows и доступ к сети,
   **When** запущена команда конвейера, **Then** подготовлены зависимости,
   проект скомпилирован и результат имеет проверяемое местоположение.
2. **Given** инструменты установлены в стандартной поставке среды разработки,
   **When** запускается команда, **Then** они обнаруживаются без ручного изменения исходников.

### User Story 2 - Повторная и автоматическая сборка (Priority: P2)

Разработчик повторяет ту же команду после изменения кода; предыдущие загрузки
и скомпилированные зависимости переиспользуются. Автоматическая проверка использует тот же путь.

**Why this priority**: Убирает повторную настройку и расхождения локальной среды и CI.
**Independent Test**: Два запуска подряд завершаются успешно, второй использует
существующие инструменты и кеш зависимостей.
**Acceptance Scenarios**:
1. **Given** успешно собранная рабочая копия, **When** команда запущена повторно,
   **Then** не требуется заново устанавливать инструменты и пересобирать неизменённые зависимости.
2. **Given** ошибка загрузки, компиляции или тестов, **When** этап завершается,
   **Then** конвейер останавливается с ненулевым кодом, указывает этап и сохраняет диагностику.

### Edge Cases

- Отсутствуют обязательные SDK: сообщить точные компоненты и остановиться.
- Сеть недоступна при первой сборке: сохранить диагностическую ошибку и возможность повторить.
- Путь проекта/инструментов содержит пробелы: передавать аргументы раздельно.
- Есть внешний каталог зависимостей: использовать его без сброса или удаления чужих изменений.
- Ошибка тестов не превращается в успешный результат; игровые данные не загружаются.
- Устаревший/несовместимый кеш: явно сообщить проблему, не удалять каталоги автоматически.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Проект MUST реально компилироваться на текущей Windows x64 машине.
- **FR-002**: Разработчик MUST запускать подготовку и сборку одной командой из обычного терминала.
- **FR-003**: Инструменты MUST обнаруживаться без привязки к компьютеру разработчика.
- **FR-004**: Зависимости MUST соответствовать зафиксированным версиям проекта;
  повторный запуск MUST использовать существующие загрузки и кеши.
- **FR-005**: Конвейер MUST останавливать работу при ошибке и сохранять диагностические журналы.
- **FR-006**: Базовые тесты MUST быть выполнены; запуск игры с данными проверяется отдельно.
- **FR-007**: Автоматическая проверка Windows MUST использовать тот же конвейер,
  документация MUST объяснять первый и повторный запуск и расположение результатов.
- **FR-008**: Стек и существующие изменения macOS MUST сохраняться;
  неподтверждённая macOS совместимость MUST быть явно отмечена.

### Key Entities

- Набор инструментов: обнаруженные компиляторы, SDK и средства сборки.
- Кеш зависимостей: локальные загрузки и скомпилированные пакеты.
- Запуск сборки: параметры, этап, результат, журналы и выходные файлы.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Нативная Windows сборка всех C++ целей и Rust workspace завершается с кодом 0.
- **SC-002**: Базовые тесты проходят без игровых данных; ошибки не скрываются.
- **SC-003**: Два последовательных запуска одной команды успешны;
  второй не переустанавливает инструменты и не перестраивает неизменённые зависимости.
- **SC-004**: README содержит одну команду запуска и ссылку на диагностику/результаты;
  Windows CI запускает этот же конвейер.

## Assumptions

- Windows x64 — текущая задача; переносимость на macOS не объявляется проверенной.
- Имеющиеся лицензированные инструменты разработки используются повторно.
- Первая подготовка может требовать сеть и место на диске; системные SDK не заменяются вручную.
- Существующие игровые данные, упаковка/подпись и полный запуск игры вне объёма этой задачи.
