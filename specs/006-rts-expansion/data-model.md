# Data model

Все новые данные принадлежат одной сессии миссии; `CWR_Clear` очищает их, callbacks не владеют экономикой. Текущие индексы CWR_RTS не менять без обновления потребителей и тестов. Конкретные дополнительные индексы зафиксировать при T002.

| Сущность | Поля и ограничения | Связи |
|---|---|---|
| FactionDefinition | уникальный id, название, side, HQ class, каталог разрешённых типов | одна активная сторона за сессию |
| BuildDefinition | уникальный typeId, factionId, className, cost >= 0, duration > 0, prerequisites, роль | BuildingInstance, ProductionOrder |
| BuildingInstance | объект, typeId, owner; только живые завершённые здания выполняют роль | база, склад, производство |
| ProductionOrder | id, typeId, оплаченная цена, deadline, состояние | queued → producing → ready → deployed; отмена размещения оставляет ready |
| ResourceNode | id, позиция, remaining >= 0 | несколько сборщиков; списание только фактически собранного объёма |
| Harvester | объект, owner, cargo, capacity > 0, nodeId, depot, состояние, deadline/progress timestamp | idle → movingToNode → collecting → returning → unloading → movingToNode |
| ControlGroups | 10 списков ссылок на юниты | только живые принадлежащие игроку объекты; один юнит может входить в несколько групп |
| MoveFeedback | позиция принятого приказа, время появления, lifetime | один последний маркер; удаляется по времени/очистке сессии |
| CameraConfig | focus, pitch, distance, min/max, FOV | min <= distance <= max; единая точка фокуса |

Инварианты: 0 <= cargo <= capacity; 0 <= remaining; credits >= 0. Доход поступает ровно один раз за фактически разгруженный груз. Уничтоженный сборщик теряет груз, уничтоженный склад выбирается заново из своих живых складов; без склада сборщик ожидает с грузом. Истощённый узел заменяется ближайшим доступным, отсутствие узлов переводит машину в idle. Недостижимая цель после ограниченного таймаута выдаёт сообщение и переводит в idle с сохранением груза; бесконечные попытки запрещены. Таймаут и интервал сбора задаются в конфигурации, измеряются игровым временем. На паузе доход не растёт.

## US1: схема состояния перед реализацией

Сохраняются индексы 0–19. Индекс 20: десять отдельных массивов групп 0–9; индекс 21: [] либо [позиция, игровое время принятия приказа]. Владелец init/session; Start и Clear сбрасывают оба поля. groups.sqf содержит очистку/назначение/выбор; tick удаляет погибших и чужих участников без изменения статуса игрока. Каталог/заказы откладываются до US2.

## US2: конкретный контракт состояния

CWR_RTS[22] = склады (объекты); [23] = тип общего строительного заказа (0 Barracks, 1 Depot); [24] = экстракторы; [25] = узлы; [26] = последнее время обновления экономики. Длина = 27. Тип заказа неизменяем от оплаты до размещения. State[3]/[18] остаются общими deadline/READY.

Harvester record: [vehicle, driver, cargo, phase, nodeIndex, deadline, targetPosition, crewGroup, deliveredTotal, reason, depot]. Фазы 0 idle, 1 movingToNode, 2 collecting, 3 returning, 4 unloading, 5 waitingDepot. cargo в [0,100], node remaining >=0, phase deadline считается по time. Цель выдаётся один раз при переходе, а не каждые 0.1с. Списание узла и увеличение груза происходят вместе. Разгрузка сначала обнуляет груз/меняет фазу, затем начисляет credits и deliveredTotal ровно на разгруженный объём. Повторный tick с тем же time ничего не добывает и не начисляет.

Node record: [object, position, remaining, markerName]. Два начальных узла по 1200; ресурс конечен. Обычный doMove останавливает цикл своей машины с сохранением груза. Явная ресурсная команда возобновляет цикл. Живые машины входят в общий selectable/group/health контракт, список state[5] остаётся пехотой.
