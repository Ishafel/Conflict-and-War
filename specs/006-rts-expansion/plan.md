# Implementation Plan: развитие RTS

**Branch**: текущая `develop` (планирование без смены ветки) | **Date**: 2026-10-31 | **Spec**: [spec.md](spec.md)
**Input**: `specs/006-rts-expansion/spec.md`

## Summary

Четыре поставки: US1 управление/камера → US2 ресурсы → US3 здания → US4 сторона. Начать с улучшения текущего играбельного среза. Продолжить существующую миссию и native UI; экономика остаётся внутри одного явного состояния миссии и одного tick. Общий каталог вводится для реальных новых типов, а не как универсальный framework.

## Technical Context

**Language/Version**: C++20/C11, Rust workspace, текущие SQF/SQS; Python >=3.11 для Spec Kit.
**Primary Dependencies**: CMake/Ninja, Clang, vcpkg, SDL3, OpenGL 3.3, OpenAL, ImGui, Catch2, Trident — без замены.
**Storage**: память одиночной сессии; определения собственного контента в `content/cw/`; внешние модели остаются во внешней установке.
**Testing**: Catch2 для вынесенных чистых правил native UI; Trident для миссии, экономики, клавиатуры и визуальной интеграции; нативные игровые снимки.
**Target Platform**: Windows x64 и macOS Apple Silicon arm64; Intel presets необязательны.
**Project Type**: глубокая модификация desktop game.
**Performance Goals**: сохранить один tick около 0.1 с, bounded overlays только для видимых объектов; сравнить frame-time до/после на одном хосте и одной сцене с 50 юнитами, не допустить ухудшения медианы более 10%.
**Constraints**: нет сторонних данных в repo/CI, скрытых mutable globals, копирования экономики по сторонам, массового переименования Poseidon/CWR/OFPR.
**Scale/Scope**: один Everon, две стороны, десять групп, один ресурс, пять типов базы на сторону, один тип сборщика на сторону.

## Constitution Check

До Phase 0: PASS — стандартные артефакты Spec Kit, стек/совместимость/лицензии сохранены. Поведение не меняется в этой подготовке.
После Phase 1: PASS — явный владелец состояния, единая экономика/проверка площадки, FR и критерии связаны с задачами. Нет необоснованных отклонений. Нативные проверки обеих платформ запланированы, но пока не выполнены.

## Этапы и точки приёмки

1. **US1 / MVP** — маркер, группы, здоровье, ширина, удаление кнопки, камера. FR-001–005; приёмка SC-001/002 на существующей пехоте.
2. **US2 / экономика** — общий каталог как необходимая основа склада/экстрактора, узлы, машина состояний, доставка, индикация и сброс. FR-006/007/011; приёмка SC-003. Игровой путь для теста US2 использует стартовый экстрактор.
3. **US3 / база** — развить каталог до склада, завода и обороны; зависимости, очереди, READY и создание машины заводом. FR-008/009; приёмка SC-004 для одной стороны.
4. **US4 / сторона** — выбор перед стартом и определения East; общая логика, проверенные классы. FR-010; приёмка SC-004 для обеих сторон.
5. **Общая приёмка** — регрессии 003, производительность, полные сценарии SC-005 на обеих платформах. Точная оценка календарных сроков возможна после проверки классов и первой поставки.

## US1: проверка масштаба

FR-005: read-only Trident `triGetRTSUnitRect [idc,object]` возвращает проецируемые границы в пикселях из RTSViewport. Сценарий сравнивает одну модель на прежней и новой ближайшей камере; команда не изменяет игру, регистрируется в существующем тестовом наборе.

## US2: проектирование перед реализацией (2026-10-31)

FR-006/007/009/011: сохранить индексы 0–21, расширить состояние до 27 полей: 22 склады (список объектов), 23 тип текущего заказа здания, 24 экстракторы, 25 узлы, 26 время последнего экономического обновления. Catalog содержит только Barracks и Camp (склад); одна общая строительная очередь со старой семантикой оплаты/READY. Прежние поля казармы и сроки остаются совместимыми. У типа нет своей копии экономики или placement validation.

Первый Truck5t с водителем SoldierWB выдаётся при старте отдельно от списка пехоты. Добыча запускается явно и не меняет стартовый баланс. Ресурсы обозначены собственными кругами UI и маркерами на карте, физические контейнеры — существующие ReammoBoxWest из внешней установки. Склад Camp стоит 600, строится 8 секунд. Ёмкость машины 100, порция 25 за 1 игровую секунду, разгрузка 2 секунды, единица = 1 credit, радиус приёма 12 м, timeout пути 45 секунд. Два узла по 1200 единиц. Водитель и его группа принадлежат сессии, очищаются вместе с машиной.

Нативный viewport получает optional placementClassExpression вместо постоянной модели, сбрасывает preview при смене класса; resourceNodes возвращает только представление узлов, не выполняет добычу. Остальные контролы сохраняют прежний контракт. Проверить реальные модели/геометрию и движение до принятия классов. Завод, оборона, вторая сторона не входят в US2. Constitution Check PASS до реализации: текущий стек, одна миссия/один tick, явное состояние/лицензии/две платформы без ложных утверждений.

US2 runtime-коррекция: штатный AI грузовика остановился рядом с целевой точкой, но вне 7 м, и корректно сработал path timeout. Зона погрузки/разгрузки увеличена до 12 м с учётом габаритов машины; движение и фактическая дистанция остаются обязательными, таймер не заменяет прибытие. См. arrival_diagnostic в build/rts-us2-route.

## FR-013: уточнение управления мышью

Владелец отменил движение через ЛКМ. Разделить ветки существующего CWR_WorldClick: ЛКМ только CWR_SetSelection (включая очистку пустого выбора); ПКМ только контекстные приказы; размещение остаётся прежним. C++ viewport менять не требуется. Подсказки описывают ПКМ явно. Проверки: новый commands.test.sqf с native кнопками и отдельными отрицательными проверками ЛКМ на земле/ресурсе, затем mouse/feedback/economy для реальных приказов и размещения. Constitution Check PASS; экономика/стек/структура состояния не меняются.

## FR-003: постоянные HP солдат

По уточнению владельца постоянно включать своих живых солдат state[5] в существующий healthUnits callback, включая здоровых без выделения. Техника сохраняет текущую политику; общий renderer, анимированная привязка к голове и clip не меняются. Native health.test проверяет 100/50/10% без выделения, смену выделения, скрытие, смерть/удаление и отсутствие постороннего солдата в собственном реестре; снимки 720p/1080p. Constitution Check PASS: без новой глобальной переменной, дублирования renderer или смены стека.
